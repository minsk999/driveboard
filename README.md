# DriveBoard

> **팀원 설치 (3줄)**
> 1. [Releases](https://github.com/minsk999/driveboard/releases/latest) 에서 `DriveBoard-Windows.zip` 을 받습니다.
> 2. 아무 폴더(예: `D:\Apps\DriveBoard`)에 **압축을 풉니다**(압축 파일 안에서 바로 실행하지 마세요).
> 3. `DriveBoard.exe` 를 더블클릭합니다.
>
> 처음 실행할 때 **「Windows의 PC 보호」** 파란 창이 뜨면 **[추가 정보] → [실행]** 을 누르세요.
> 서명하지 않은 앱이라 그렇습니다(새 버전마다 한 번씩 다시 물을 수 있어요). 설치 프로그램도, 관리자 권한도 필요 없습니다.

영상팀 PC 의 드라이브(SSD·HDD·외장 디스크·USB 메모리·NAS)가 **무엇으로 차 있는지** 아이폰 「저장 공간」처럼 카테고리별로 보여 주고,
그 자리에서 **휴지통으로 보내거나 다른 드라이브·NAS 로 옮기거나 복사하는** Windows 데스크톱 앱입니다.
프로젝트 폴더를 **광고주·시간·연월별로 묶어 영상 미리보기와 함께** 보여 줍니다.

- 저장 공간: 모든 드라이브 합산 막대 + 정리 추천(캐시·오래된 렌더·중복·큰 파일·오래된 폴더·휴지통) + 드라이브 카드
- 드라이브 상세: 카테고리 / 폴더 / 트리맵 탭
- 프로젝트: 광고주별 · 시간순 · 연·월별, 카드에 마우스를 올리면 음소거 미리보기
- 목록에서 골라 **휴지통으로**, **다른 위치로 이동**, **복사**(드래그 앤 드롭 가능 — Ctrl 을 누르고 놓으면 복사). 이동·복사는 **되돌리기** 가능
- 외부로 나가는 요청은 **업데이트 확인 1번뿐**(GitHub 릴리스 조회, 설정에서 끌 수 있음). 모든 데이터는 이 PC 안에만 저장

설계 정본은 `SPEC.md`(1차)와 `SPEC-2.md`(2차 — 팀 배포·프로젝트·미리보기·NAS·복사)입니다. 둘이 다르면 `SPEC-2.md` 가 이깁니다.

## 소스로 실행 (개발자)

1. **Python 3.10 이상**(Windows 10/11). 필수 의존성은 없습니다(표준 라이브러리만 씁니다).
2. (선택, 권장) 네이티브 창으로 띄우려면 `pip install pywebview` — 없으면 기본 브라우저로 열립니다.
   이때는 `run.cmd` 로 띄운 서버가 창 없이 계속 떠 있으니, 끝낼 때는 작업 관리자에서 `pythonw.exe` 를 끄거나
   `run-dev.cmd` 로 띄운 뒤 그 창을 닫으세요.
3. (선택) 영상 미리보기를 만들려면 `ffmpeg.exe`·`ffprobe.exe` 를 `bin\` 폴더에 두거나 PATH 에 두세요(배포본에는 들어 있습니다).

- **`run.cmd` 더블클릭** — 콘솔 창 없이 실행(`pythonw app.py`, 없으면 `pyw`/`python`).
- **`run-dev.cmd`** — 콘솔에 로그가 보이는 개발 실행. 창을 닫으면 앱도 꺼집니다.
- 직접 실행:
  ```
  python app.py                 # 창(pywebview) 또는 브라우저
  python app.py --no-open       # 서버만(브라우저로 http://127.0.0.1:8790/ 접속)
  python app.py --port 8800     # 시작 포트(막혀 있으면 +1 씩)
  python app.py --fake <폴더>   # 가짜 드라이브로(개발·시험용, 아래 참고)
  python app.py --multi         # 이미 떠 있어도 하나 더(개발용)
  ```
- **한 번만 실행**: 이미 떠 있으면 두 번째 실행은 기존 창을 앞으로 불러오고 끝납니다(브라우저 모드면 그 주소를 엽니다).
  `--no-open`(서버만)과 `--multi` 는 이 검사를 하지 않습니다.
- 처음 켜면 아직 스캔 전이라 비어 있습니다. **「모든 드라이브 스캔」** 을 누르세요. 스캔 중에도 앱을 쓸 수 있습니다.
  스캔 결과는 저장되어 다음 실행 때 바로 보입니다(드라이브 사용량이 크게 달라지면 「다시 스캔 권장」 표시).
- 「모든 드라이브 스캔」(위쪽 [모두 스캔])은 **내장 드라이브만** 훑습니다. 외장 디스크·USB 메모리·NAS 는 카드의 [스캔] 을 누르거나,
  설정에서 그 드라이브의 「스캔 대상」을 켜면 함께 훑습니다(네트워크는 느리기 때문).

## 외장 디스크 · USB 메모리 · NAS

- 외장 HDD/SSD 와 USB 메모리, **드라이브 문자로 연결한(매핑한) NAS** 는 자동으로 목록에 나옵니다.
- 드라이브 문자 없이 쓰는 NAS(예: **ORICO** — 탐색기 「네트워크」에서 녹색 띠가 있는 공유 폴더로 보이는 것)는
  **「NAS 추가」** 로 등록합니다. `\\ORICO\공유이름` 또는 `\\192.168.0.10\공유이름` 을 넣거나,
  장치 이름(`\\ORICO`)만 넣고 **[공유 찾기]** 로 목록에서 고르세요. 찾지 못하면 공유 이름까지 직접 입력하면 됩니다.
- NAS 가 꺼져 있거나 응답하지 않아도 앱은 멈추지 않습니다(그 위치만 「연결 안 됨」, 약 3초 안에 판단).
- **빠진 외장 디스크도 「연결 안 됨 · 마지막 스캔 …」 회색 카드로 남아** 무엇이 들어 있었는지 볼 수 있습니다(조작은 안 됨).
  다시 꽂으면 드라이브 문자가 바뀌어도 볼륨 시리얼로 같은 장치로 알아봅니다. 필요 없으면 카드에서 [기록 지우기].
  (기록 삭제는 DriveBoard 가 저장한 스캔 결과만 지웁니다. 장치의 파일은 건드리지 않습니다.)
- 외장·NAS 에서는 Windows 시스템 폴더 보호 규칙을 적용하지 않습니다(그 안의 `Users`·`Windows` 같은 이름의 폴더도 고를 수 있음).
  대신 최상위 자체와 `$RECYCLE.BIN`·`System Volume Information`·`@eaDir`·`#recycle`·`#snapshot`·`.DS_Store` 는 막습니다.

## 프로젝트 보기

- 프로젝트 폴더 판정(스캔 결과만 보고, 디스크를 다시 훑지 않음):
  1. 설정의 **「프로젝트를 모아 둔 폴더」** 의 바로 아래 폴더
  2. 이름이 날짜로 시작하는 폴더(`260803_…`, `20260803_…`, `2026-08-03 …`, `2026-08_…`)
  3. 바로 안(또는 한 단계 아래)에 `aep`·`aepx`·`prproj`·`drp` 가 있는 폴더
     — 단 **모음 폴더는 아닙니다**: 한 단계 아래 aep 가 날짜 이름 폴더(그 자체로 프로젝트) 안에 있거나,
     `AE`·`PR`·`aep`·`프로젝트` 같은 도구 폴더가 아닌 하위 폴더 둘 이상에 흩어져 있으면(`D:\Projects\260803_…\…aep`)
     `Projects` 를 하나의 프로젝트로 보지 않고 안쪽 폴더들을 각각 프로젝트로 봅니다.
  - 위쪽 폴더가 이미 프로젝트면 그 안의 폴더는 따로 세지 않습니다(`260805_수정본` 은 부모 프로젝트에 속함). 1MB 미만·캐시·시스템 폴더는 뺍니다.
  - 잘못 잡힌 폴더는 「이 폴더는 프로젝트가 아님」, 못 잡힌 폴더는 그 상위 폴더를 「프로젝트를 모아 둔 폴더」로 지정하세요.
- **팀 파일명 규칙(BRC)** 으로 이름을 읽습니다: `날짜_광고주_캠페인_페이지p_작업내용_해상도_작업자_@작업종류_작업구분`
  예: `260803_소담코스_녹차_진정크림_배너결합_KMS` → 2026-08-03 · 광고주 소담코스 · 제목 「녹차 진정크림 배너결합」 · 작업자 KMS.
  이름에 날짜가 없으면 폴더 안 가장 최근 파일의 수정 시각을 씁니다.
- 「광고주 정리」에서 같은 광고주의 다른 표기를 **합치고**(예: `한결` → `한결증권`), 작업자 이니셜에 이름을 붙입니다.
  **팀 설정 내보내기/가져오기** 로 광고주 별칭·작업자·분류 규칙을 JSON 파일 하나로 팀원과 나눌 수 있습니다
  (가져오기는 먼저 바뀔 내용을 보여 주고, 기존 항목을 지우지 않으며, 이 PC 에 없는 경로의 규칙은 따로 알려 줍니다).
- 미리보기 영상 = 프로젝트 안 영상 중 **렌더 > 기타 영상 > 촬영 소스** 순, 같은 순위면 **수정 시각이 가장 최근**인 것.

## 영상 미리보기 (ffmpeg)

- H.264(8비트 4:2:0)/AAC 의 `mp4`·`mov`·`m4v` 와 `webm` 은 앱 안에서 바로 재생합니다.
- ProRes·DNxHR·HEVC·알파 채널 영상 등은 **ffmpeg 로 작은 미리보기(폭 960, 최대 90초, H.264)** 를 만들어 재생합니다.
  포스터(정지 화면)도 ffmpeg 로 만듭니다. 만들기는 뒤에서 낮은 우선순위로 돌고, 화면에 보이는 카드부터 만듭니다.
- 미리보기는 데이터 폴더의 `previews\` 에 모아 두고, **상한(기본 2GB, 설정에서 0.5~50GB)** 을 넘으면 오래 안 본 것부터 지웁니다.
  설정의 「미리보기 캐시 비우기」로 언제든 지울 수 있습니다(원본 영상은 건드리지 않습니다).
- ffmpeg 를 찾는 순서: 환경 변수 `DRIVEBOARD_FFMPEG`(ffmpeg.exe 또는 그 폴더) → 앱 폴더의 `bin\ffmpeg.exe` → PATH.
  없으면 바로 재생되는 영상만 브라우저가 포스터를 만들고, 나머지는 「미리보기를 만들 수 없어요」로 표시합니다.
- 화면의 영상은 서버가 응답마다 발급한 무작위 주소(`/media/<토큰>`)로만 열립니다. 주소에 경로가 없고,
  알려진(연결된) 드라이브·미리보기 캐시 안의 영상·이미지 파일만 내보냅니다. 클라우드 자리표시자·링크는 열지 않습니다.

## 안전 장치 — 꼭 알아 두세요

- **휴지통으로 보낸 용량은 그 드라이브의 휴지통을 비워야 확보됩니다.** Windows 휴지통은 드라이브마다 따로입니다.
  D: 에서 보낸 파일은 D: 의 휴지통에 있고, D: 의 휴지통을 비워야 D: 에 공간이 생깁니다.
  휴지통으로 보낸 것은 Windows 휴지통에서 복원할 수 있습니다(앱의 자동 되돌리기는 없습니다).
  휴지통보다 큰 파일은 Windows 가 「영구 삭제할까요?」를 묻습니다(그대로 지우지 않도록 경고를 켜 둡니다).
- **NAS·USB 메모리에는 휴지통이 없습니다.** 그런 위치에서는 「휴지통으로」가 막히고 버튼이 **「삭제(복구 불가)」** 로 바뀝니다.
  빨간 확인 창에서 체크해야만 지웁니다. 지운 것은 **되살릴 수 없습니다.** (휴지통이 있는 드라이브에서도 직접 고르면 영구 삭제할 수 있습니다.)
- **휴지통 비우기는 영구 삭제**입니다. 확인 창을 한 번 더 거칩니다.
- 영구 삭제는 **확인 창에서 본 양보다 더 지우지 않습니다.** 스캔한 뒤(또는 확인한 뒤 작업이 차례를 기다리는 동안) 동료가 그 폴더에 파일을 넣었다면
  지우지 않고 「다시 스캔해서 확인해 주세요」로 멈춥니다.
- **이동은 복사 → 검증 → 원본 삭제** 순서입니다.
  - 파일마다 임시 이름(`.dbpart`)으로 복사하고 검증한 뒤에 제 이름으로 바꿉니다. 대상에 같은 이름이 있으면 덮어쓰지 않고 ` (2)` 를 붙입니다.
  - 검증 수준: `크기만` / `빠른 확인`(기본, 크기 + 처음·가운데·끝 1MB 비교) / `전체 비교`(전체 해시).
  - **원본은 그 항목의 모든 파일이 검증된 뒤에만** 지웁니다. 지우기 직전에 원본이 바뀌었으면 원본을 남깁니다.
  - 중간에 취소·실패하면 이번 작업이 만든 사본만 치우고 원본은 그대로 둡니다.
  - 대상은 원래와 **같은 상대 경로**(예: `D:\Projects\A` → `H:\Projects\A`)라 AE 상대 경로 재연결이 됩니다.
    「폴더 선택…」으로 고른 폴더로 보내면 그 폴더 바로 아래에 둡니다.
  - 남은 공간 + 여유 1GB 가 안 되면 시작하지 않습니다.
  - 옮기는 중에 외장 디스크가 빠지거나 NAS 연결이 끊기면 그 파일은 실패로 끝나고 **원본은 그대로** 남습니다(「장치 연결이 끊겼어요」).
    원본을 지우는 단계에서 원본 장치가 빠지면 남은 원본은 지우지 않고 사본도 대상에 남깁니다(작업 기록이 「원본과 대상에 나뉘어 있어요」라고 알립니다).
  - **되돌리기는 같은 디스크가 같은 문자에 있을 때만** 합니다. 작업 때의 볼륨 일련번호와 다르면(다른 외장 디스크를 같은 문자로 꽂은 경우)
    거절하고, 원래 디스크를 다시 연결하면 그때 되돌릴 수 있습니다.
  - 이동 중에 앱이 꺼지거나 PC 가 멈춰도 다음 실행 때 작업 기록이 **항목마다 실제로 어디까지 했는지**(옮김 / 지우던 중 / 손대지 않음)를 알려 줍니다.
  - 이동·복사·삭제가 진행 중일 때 창을 닫으면 먼저 묻습니다. 원본을 지우던 항목은 마저 지운 뒤(최대 2분) 닫힙니다 — 중간에 끊으면 원본과 대상에 나뉘기 때문입니다.
- **복사**는 이동에서 원본 삭제만 뺀 것입니다(같은 복사·검증 경로). 같은 드라이브 안으로 복사하려면 대상 폴더를 골라야 합니다.
  복사 **되돌리기**는 그 작업이 만든 파일·폴더만 지웁니다(휴지통이 있으면 휴지통으로). 복사한 뒤 바뀐 사본,
  원본이 없어지거나 바뀐 사본은 유일본일 수 있어 지우지 않고 남깁니다. 복사한 뒤 원본을 다른 곳으로 **옮겼다면**
  원본 자리가 비어 있으므로 복사 되돌리기는 거절됩니다 — 이동을 먼저 되돌리면 복사 되돌리기가 됩니다.
- **보호 경로**는 아예 고를 수 없습니다: 드라이브 최상위, `Windows`·`Program Files`·`ProgramData`·`$Recycle.Bin`·`System Volume Information` 등 시스템 폴더,
  `pagefile.sys` 같은 시스템 파일, `Users` / `Users\<이름>` / `AppData` 자체와 표준 폴더(바탕 화면·문서·다운로드 …) 자체(안의 내용물은 허용),
  「앱·시스템」으로 분류된 항목, 이 앱의 폴더와 데이터 폴더. (외장·NAS 의 규칙은 위 「외장 디스크 · USB 메모리 · NAS」 참고.)
- **이 PC 자신의 공유**(`\\localhost\C$`, `\\127.0.0.1\…`, `\\내PC이름\…`)는 「NAS 추가」로 등록할 수 없고 다루지도 않습니다 —
  그 아래는 `C:\Windows` 일 수 있는데 NAS 규칙(최상위만 보호)이 걸리기 때문입니다. 드라이브 문자(C: 등)로 다뤄 주세요.
- 링크·정션·OneDrive 「필요할 때 다운로드」 자리표시자는 따라가지도, 옮기지도, 지우지도, 미리보기로 열지도 않습니다(그래서 OneDrive 안 파일은 다룰 수 없습니다).
- 연결 안 된 장치의 회색 카드 안 항목은 모두 「연결되지 않은 장치라 다룰 수 없어요」로 막힙니다.
- 작업은 한 번에 하나씩 순서대로 돕니다. 작업 기록은 최근 200개를 보관합니다.
- 캐시 항목을 다룰 때 After Effects·Premiere Pro·Media Encoder 가 켜져 있으면 결과에 경고를 남깁니다(막지는 않습니다).

헤드리스 Chromium 은 H.264 를 풀지 못해 재생 확인은 ffmpeg 로 만든 VP9 `webm` 으로 합니다.

가짜 드라이브(`--fake <폴더>`): 그 아래 `C`, `D` … 폴더 하나가 드라이브 하나. `_drive.json` 에 라벨·종류·용량·`external`·`has_bin`, 휴지통은 `.fakebin`.
`N-` 로 시작하는 폴더는 가짜 NAS 입니다(`_drive.json` 의 `unc`, 예 `\\ORICO\영상백업`). **앱에서 「NAS 추가」로 그 UNC 를 등록해야** 목록에 나옵니다
(`[공유 찾기]` 에 `ORICO` 를 넣으면 보입니다). 실제 영상 클립은 ffmpeg 로 한 번 만들어 캐시해 둡니다(`--no-video` 면 자리표시자).
★ 희소 파일을 **이동·복사**하면 실제로 0 을 써서 디스크를 채웁니다. 이동 시험은 작은 실제 파일로 하세요(`tests/e2e.js` 가 그렇게 합니다).
업데이트 확인을 끄려면 `DRIVEBOARD_NO_UPDATE_CHECK=1`.

배포본 만들기: `build.bat`(ffmpeg 내려받기·sha256 확인 → 시험 → PyInstaller → `dist\DriveBoard-Windows.zip`).
`v*` 태그를 올리거나, GitHub Actions 의 **release → [Run workflow]** 에 태그(예 `v1.0.0`)를 넣으면 같은 일을 하고 릴리스에 붙입니다(태그 = `v` + `core/version.py` VERSION, `-` 가 있으면 시험판). ffmpeg 고지는 `THIRD-PARTY.txt`.

## Windows 에서 처음 확인할 것

이 앱은 Linux 컨테이너에서 개발·검증했습니다. **Windows API 를 부르는 코드는 한 번도 실제로 돌려 보지 않았습니다.**
처음 Windows 에서 쓸 때 아래를 순서대로 확인해 주세요.

1. **`python tests\win_selftest.py` 를 먼저 실행**하고 결과 표(PASS/FAIL)를 그대로 알려 주세요.
   자기가 만든 파일만 다룹니다(%TEMP% 와 두 번째 드라이브 최상위에 `DriveBoard-selftest-…` 폴더를 만들어 휴지통 보내기·이동·복사·되돌리기를 해 보고 치웁니다.
   휴지통 비우기는 하지 않고, 외장·USB·NAS 에는 아무것도 쓰지 않습니다).
   탐색기 열기까지 보려면 `--reveal`, NAS 공유 목록까지 보려면 `--nas ORICO`(장치 이름이나 IP).
2. **드라이브 목록**(`GetLogicalDriveStringsW`·`GetDriveTypeW`·`GetVolumeInformationW`·`GetDiskFreeSpaceExW`): 고정 드라이브가 모두, 라벨·용량·남은 공간이 탐색기와 같은 숫자로 나오는지.
   SSD/HDD 구분(`IOCTL_STORAGE_QUERY_PROPERTY` 의 seek penalty)이 맞는지. `subst` 로 만든 문자는 빠지고, 한 볼륨에 문자가 둘이면 한 번만 나오는지.
3. **외장 디스크 판정**: USB 로 연결한 외장 HDD/SSD 가 「외장」(케이블 달린 디스크 아이콘)으로, USB 메모리가 「USB」로 나오는지
   (`BusType` = USB·1394·SD·MMC). 내장 NVMe·SATA 가 외장으로 잘못 나오지 않는지. 기본으로 「모든 드라이브 스캔」에서 빠지는지.
4. **휴지통 유무**: 내장·외장 NTFS 디스크는 「휴지통으로」, USB 메모리(FAT32/exFAT)와 NAS 는 「삭제(복구 불가)」로 바뀌는지.
   USB 메모리에서 「휴지통으로」를 누르면 거부되는지(앱 + Windows 쪽 이중 확인). 이동식(`DRIVE_REMOVABLE`) 매체는
   `$RECYCLE.BIN` 폴더가 남아 있어도 「휴지통 없음」이어야 합니다(셸이 이동식 매체에서는 휴지통을 쓰지 않습니다).
5. **휴지통 보내기**(`SHFileOperationW`, `FOF_ALLOWUNDO|FOF_WANTNUKEWARNING|…`): 정말 휴지통으로 가는지, 휴지통보다 큰 항목에서 「영구 삭제」 경고가 뜨는지.
   그 경고·「사용 중인 파일」 창은 앱 창에 붙지 않고(hwnd 없음) 뒤에 숨을 수 있습니다.
6. **휴지통 크기·비우기**(`SHQueryRecycleBinW`·`SHEmptyRecycleBinW`): 드라이브별 휴지통 크기가 맞는지, 비우기가 그 드라이브만 비우는지(소리·진행 창 없이).
7. **이동·복사** 실전 전에 작은 폴더로: 다른 드라이브로 옮기기 → 되돌리기, 복사 → 되돌리기(복사본만 사라지고 원본은 그대로) → 원래대로인지.
   긴 경로(260자 넘는 폴더)도 한 번. 같은 드라이브 안 복사는 「폴더 선택…」을 요구하는지.
8. **NAS**: 드라이브 문자로 매핑한 NAS(`Z:`)가 「네트워크」로, 라벨이 공유 경로(`WNetGetConnectionW`)로 나오는지.
   「NAS 추가」에 `\\ORICO`(또는 IP)를 넣고 [공유 찾기] 를 누르면 공유 목록(`NetShareEnum`)이 뜨는지, 등록 뒤 용량이 맞는지.
   NAS 전원을 끈 채 앱을 켜도 몇 초 안에 「연결 안 됨」으로 뜨고 화면이 멈추지 않는지. NAS 로 작은 폴더 복사 → 되돌리기(영구 삭제 확인).
   NAS 로 옮기는 중 랜선을 뽑으면 작업이 「장치 연결이 끊겼어요」로 끝나고 원본이 남는지(버릴 폴더로).
9. **외장 디스크 빼기·다시 꽂기**: 스캔한 외장 디스크를 빼면 회색 「연결 안 됨」 카드로 남는지, 다른 USB 포트(다른 문자)로 꽂아도 같은 장치로 알아보는지.
   장치를 빼는 중 이동이 진행 중이면 원본이 남는지(작은 시험 폴더로).
10. **탐색기에서 보기**(`explorer /select,`)가 그 파일을 선택한 채 열리는지.
11. **Adobe 실행 중 경고**(`tasklist`): AE 를 켠 채 캐시 폴더를 다룰 때 결과에 경고가 남는지, 콘솔 창이 깜박이지 않는지.
12. **스캔 속도**: 실제 HDD(7.27TB)에서 걸리는 시간. 컨테이너에서는 메모리 캐시된 100만 파일이 11초였지만, 실제 디스크는 디스크 속도에 묶입니다.
    NAS 스캔은 더 느립니다(속도 표시·취소가 되는지). 접근 거부 폴더는 「확인 불가」로 세고 오류 수로 표시됩니다(관리자 권한 없이 동작).
    정션(`Documents and Settings` 등)·OneDrive 자리표시자를 두 번 세지 않는지.
13. **창**: `pywebview`(WebView2) 창이 1360×860(최소 1100×720)으로 뜨는지, 타이틀바가 다크(`DwmSetWindowAttribute` 20/35/36)인지,
    창을 닫으면 프로세스도 끝나는지. pywebview 가 없을 때 기본 브라우저로 열리는지.
14. **「폴더 선택…」**: 이동·복사 팝오버의 「폴더 선택…」이 네이티브 폴더 선택 창(pywebview `FOLDER_DIALOG`)을 앱 창 위에 띄우는지, 취소하면 아무 일도 없는지.
15. **영상 재생**: 프로젝트 카드 호버 미리보기와 시트의 플레이어가 WebView2 에서 재생·탐색(시킹)되는지(HTTP Range).
    ProRes `.mov` 가 미리보기(프록시)로 바뀌어 재생되는지, 포스터가 뜨는지, 미리보기를 만드는 동안 이동·스캔이 느려지지 않는지
    (ffmpeg 가 낮은 우선순위·콘솔 창 없이 도는지). `bin\ffmpeg.exe` 를 치웠을 때 「미리보기를 만들 수 없어요」로 바뀌는지.
16. **배포본(`DriveBoard.exe`)**: 압축을 푼 폴더에서 SmartScreen [추가 정보] → [실행] 뒤 뜨는지, `_internal\bin\ffmpeg.exe` 를 찾는지,
    버전 정보(파일 속성 → 자세히)가 맞는지.
17. **`run.cmd` 더블클릭**: 콘솔 창 없이 뜨는지(`pythonw`). 오류가 나면 `%LOCALAPPDATA%\DriveBoard\driveboard.log` 를 보내 주세요.
